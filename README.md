# فروشگاه یاشیل آرت (Yashil Art Shop)

سامانه فروشگاهی MVP با معماری جداسازی‌شده: بک‌اند Django REST Framework + فرانت‌اند Vue 2.

## ساختار پروژه

```
kaavan-shop/
├── backend/     # Django REST API (Python 3.8+, Django 4.2, SQLite)
└── frontend/    # Vue 2 SPA (vue-router, vuex, axios)
```

## راه‌اندازی بک‌اند

```bash
cd backend
python -m venv venv
source venv/bin/activate        # ویندوز: venv\Scripts\activate
pip install -r requirements.txt

python manage.py makemigrations accounts products cart orders dashboard
python manage.py migrate
python manage.py seed_demo      # ساخت دیتای نمونه + کاربر ادمین

python manage.py runserver
```

بک‌اند روی `http://127.0.0.1:8000` بالا می‌آید.

**کاربر ادمین نمونه:** `admin` / `Admin@12345`
(پنل ادمین کاستوم Vue، نه پنل پیش‌فرض جنگو — گرچه `/django-admin/` هم برای دیباگ سریع در دسترس است.)

## راه‌اندازی فرانت‌اند

```bash
cd frontend
npm install
npm run serve
```

فرانت‌اند روی `http://localhost:8080` بالا می‌آید و به‌صورت پیش‌فرض به
`http://127.0.0.1:8000/api` وصل می‌شود. برای تغییر آدرس API، متغیر محیطی
`VUE_APP_API_BASE_URL` را در یک فایل `.env.local` تنظیم کنید:

```
VUE_APP_API_BASE_URL=http://127.0.0.1:8000/api
```

## چیزی که در فاز اول (MVP) پیاده شده

- ✅ لندینگ + لیست/جزئیات محصول با فیلتر، جستجو، صفحه‌بندی
- ✅ سبد خرید سمت کلاینت (Vuex + localStorage) با اعتبارسنجی قیمت/موجودی سمت سرور
- ✅ فرآیند خرید (Checkout) و ثبت سفارش
- ✅ احراز هویت کامل: ثبت‌نام، ورود (JWT)، بازیابی رمز عبور (صفحه جداگانه طبق انتخاب شما)
- ✅ پنل ادمین کاستوم: داشبورد آماری، مدیریت محصولات (CRUD)، مدیریت سفارش‌ها
  (تغییر وضعیت)، مدیریت کاربران (فعال/غیرفعال، ارتقا به ادمین)
- ✅ ردیابی وضعیت سفارش با المان بصری «خط مسیر» (کاروان)

## بخش‌هایی که در فاز بعد اضافه می‌شوند

- چت آنلاین پشتیبانی (WebSocket)
- سیستم کدهای تخفیف
- Wishlist
- درگاه پرداخت واقعی (در حال حاضر سفارش با وضعیت «در حال بررسی» ثبت می‌شود)
- آپلود تصویر محصول از خودِ پنل ادمین (فعلاً از طریق `/django-admin/` قابل افزودن است)

پروژه اکنون آماده دیپلوی روی Render.com است — به بخش «دیپلوی روی Render.com» زیر مراجعه کنید.

## دیپلوی روی Render.com

پروژه با فایل `render.yaml` (در ریشه پروژه) کاملاً آماده دیپلوی است — یک
Blueprint شامل سه سرویس:

1. **kaavan-shop-backend** — وب‌سرویس پایتون (Django + gunicorn)
2. **kaavan-shop-db** — دیتابیس PostgreSQL رایگان
3. **kaavan-shop-frontend** — سایت استاتیک (خروجی build شده‌ی Vue)

### مراحل

1. پروژه را در یک ریپازیتوری گیت‌هاب (خصوصی یا عمومی) push کنید.
2. در داشبورد Render: **New → Blueprint** و ریپازیتوری را انتخاب کنید؛
   Render فایل `render.yaml` را خودکار تشخیص می‌دهد.
3. قبل از Apply، اگر نام سرویس‌ها را عوض کردید، مقادیر زیر را در
   `render.yaml` هم به‌روزرسانی کنید (چون آدرس‌ها به‌صورت پیش‌فرض بر اساس
   نام سرویس ساخته شده‌اند):
   - در سرویس بک‌اند: `FRONTEND_URL` و `FRONTEND_RESET_PASSWORD_URL`
   - در سرویس فرانت‌اند: `VUE_APP_API_BASE_URL`
4. دکمه **Apply** را بزنید. Render به‌صورت خودکار:
   - دیتابیس PostgreSQL می‌سازد و `DATABASE_URL` را به بک‌اند تزریق می‌کند
   - `backend/build.sh` را اجرا می‌کند (نصب پکیج‌ها، `collectstatic`،
     `migrate`، و `seed_demo` برای ساخت کاربر ادمین + دیتای نمونه)
   - فرانت‌اند را با `npm run build` می‌سازد و به‌صورت استاتیک سرو می‌کند
     (با rewrite rule برای پشتیبانی از Vue Router در حالت history)

### بعد از اولین دیپلوی

- کاربر ادمین نمونه (`admin` / `Admin@12345`) را از پنل ادمین یا
  `/django-admin/` **حتماً رمز عبورش را عوض کنید** یا حذفش کنید.
- برای ارسال واقعی ایمیل بازیابی رمز عبور (به‌جای چاپ در لاگ)، متغیرهای
  `SMTP_HOST` / `SMTP_USER` / `SMTP_PASSWORD` را در تنظیمات سرویس بک‌اند
  در داشبورد Render اضافه کنید.
- توجه: پلن رایگان Render دیسک را در هر ری‌استارت پاک می‌کند، پس تصاویر
  آپلودی در `media/` روی پلن رایگان ماندگار نیستند. برای پروداکشن واقعی
  یک Persistent Disk (پلن پولی) یا یک storage ابری (مثل S3) لازم است.
- توجه مهم‌تر: **دیتابیس PostgreSQL رایگان Render بعد از ۳۰ روز به‌طور
  خودکار حذف می‌شود** (محدودیت پلن رایگان Render، نه چیزی در این پروژه).
  برای استفاده جدی، دیتابیس را روی یک پلن پولی بسازید یا قبل از انقضا
  یک `pg_dump` بگیرید و روی دیتابیس جدید restore کنید.
- برای مهاجرت به دامنه اختصاصی، دامنه را در تنظیمات هر دو سرویس در Render
  اضافه کنید و `FRONTEND_URL` / `VUE_APP_API_BASE_URL` را متناسب با آن به‌روز کنید.

### اجرای محلی بدون Render

اجرای محلی همچنان دقیقاً طبق بخش‌های «راه‌اندازی بک‌اند/فرانت‌اند» بالا و
با SQLite کار می‌کند؛ تنظیمات Render فقط وقتی فعال می‌شوند که متغیرهای
محیطی مربوطه (`DATABASE_URL`، `RENDER_EXTERNAL_HOSTNAME` و ...) وجود داشته باشند.

## نکات فنی مهم

- سبد خرید یک مدل دیتابیسی جدا **ندارد**؛ به‌صورت عمدی سمت کلاینت پیاده شده
  تا برای کاربر مهمان هم بدون نیاز به لاگین کار کند. مسیر
  `POST /api/cart/validate/` قیمت و موجودی واقعی را از دیتابیس برمی‌گرداند.
- دیتابیس به‌صورت خودکار بین SQLite (توسعه محلی) و PostgreSQL (وقتی
  `DATABASE_URL` ست شده باشد، مثلاً روی Render) سوییچ می‌کند.
